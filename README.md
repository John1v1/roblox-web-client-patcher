# WebClient Rescue — private Websim setup

A **dark, five-step guided wizard** for one recovered Roblox WebClient build, plus a zero-flag Python installer. The site has an in-page Python install tutorial and a shorter developer fast path. It does not ask for a Roblox login or password.

The game chooser first uses browser CORS **GET** requests to RoProxy’s public username search and public-games endpoints. **RoProxy is a third party:** the username you enter is sent there; only public data is requested. If the browser blocks it, the fixed `/api/roblox-games` route attempts the same endpoints. If lookup is unavailable or incomplete, enter a numeric **Place ID** manually. Only use a **public place you own**. The place must request `version-f4a4dba57f874ad0-RobloxWebClient`; choosing a Place ID does not change Roblox’s engine assignment.

## Follow the wizard

1. **Get ready.** Install desktop Chrome and Python 3.9+ for Windows. Page 1’s “Don’t have Python? Install tutorial” opens help *inside* the page, with a link to the official Python site. “Developer tutorial” opens a compact fast path.
2. **Pick a game.** Search your public owned games by username or enter a Place ID. The selected ID is embedded in your downloaded `setup.py` and userscript. No Roblox credentials are needed.
3. **Get the files.** Download the personalized `setup.py` and verified `webclient-rescue-payload.zip`, and keep both in the **same folder**. Double-click `setup.py` (or Open with Python). No PowerShell step or command flags. It verifies the bundle, downloads/checks the pinned 101,275,588-byte wasm from the Internet Archive, then creates `overrides/` and `roblox-webclient-rescue.user.js` **beside setup.py**. Wait for the Windows completion dialog. If the browser cannot assemble the ZIP, the wizard links the three `payload.part*` files; put them next to `setup.py` and it assembles them itself. Plain uncustomized `setup.py` prompts for a Place ID.
4. **Set up Chrome.** Install Tampermonkey from the official Chrome Web Store. In Chrome, type `chrome://extensions`, find Tampermonkey → Details, turn on **Allow User Scripts** (Chrome 138+), or **Developer Mode** on older Chrome. To drag a local `.user.js` into Chrome, also turn on **Allow access to file URLs**. Drag the userscript created by the installer into Chrome, approve its Tampermonkey installation, and confirm the Dashboard switch is on. If drag/drop fails, open the file in Notepad, copy all text, and use Tampermonkey Dashboard → Add a new script → paste → save. The wizard also has a button to download a personalized backup userscript directly from the private page. In the **game tab**, press F12 → Sources → Overrides → choose the created `overrides/` folder → allow access → check **Enable Local Overrides**. Keep DevTools attached.
5. **Launch.** The final page provides `https://play.roblox.com/games/start?placeId=YOUR_PLACE_ID`. Open it in the **same tab with DevTools attached**. **DevTools must stay open while playing**; closing/detaching it stops Local Overrides. Open Sources → Overrides before a **normal Ctrl+R** reload. Do **not** hard-refresh or turn on **Disable cache**.

The payload includes the owner’s 65-file overrides ZIP with its accidentally edited 266047-byte `WebClient.js` replaced by the verified **266045-byte v3.4**, a 252-byte patch config, **19** matching avatar-compositing meshes, and the single **4,569,049-byte combined shader pack**. It contains **86 verified files** (85 CDN override paths and one userscript). `WebClient.wasm` is downloaded separately, not uploaded to Websim. The original pinned game rendered with these files; **a different owner’s place/server is not yet validated**. Avatar meshes still need a live check. The unavailable web-only audio processor is not restored. This tool does not publish/change any Roblox place or configure Chrome automatically.

## Integrity, privacy, and development

- Websim holds the payload ZIP as three `payload.part*` files under the relay’s 8 MiB upload limit. Browser code checks each part and the assembled ZIP with SHA-256 from `delivery.json`. The installer verifies the ZIP and every contained file against its embedded manifest. Wasm size/SHA-256 are pinned. Failed/resumed wasm downloads stay in a `.part` file inside the overrides version folder.
- Path validation prevents ZIP traversal. The installed userscript is restricted to the selected Place ID. No relay credentials, tokens, or Roblox login data are in published project files. Keep the **Websim project private**.
- For advanced custom folders/offline use only: optional `--overrides PATH`, `--bundle PATH`, `--parts PART1 PART2 PART3`, `--place-id ID`, and `--wasm-file PATH`. Regular users need none.
- The owner-provided source `../uploads/extrastuff.zip` has SHA-256 `82695d13d772a6f1e46b0f98c515d809e2eef313fc33a5c19e787ea8e2403d5f`. `python tools/build_payload.py` generates local `build/` ZIP/parts and `delivery.json` / `bundle-manifest.json`. Never upload the raw source ZIP or wasm.
- Local-only `websim-state.json` holds the private project, site, and target revision IDs. `tools/deploy_websim.py` uploads **only** the 18 explicitly allowlisted assets to a draft revision, verifies paths/sizes/states, and finalizes `{draft:false}`. It never changes visibility or promotes a revision. Revision 1 is finalized and must **not** be mutated; create a new revision inheriting its assets for this wizard update. The relay credential stays local in `../credentials.json`, mode 600; never print or upload it.
